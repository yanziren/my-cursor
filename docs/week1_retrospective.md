# 第一周复盘（Day 1–7）

> 供第 2、3 周需求排序用。里程碑实战请在 TUI 中对真实小项目跑通后再补充「本项目」一栏。

## 稳定完成的任务

| 类型 | 表现 | 原因 |
|------|------|------|
| 单文件 bug 修复 + pytest 验证 | 稳定 | 工具链闭环（read → edit → bash）+ Day 6 系统提示词要求改完必测 |
| 按路径读/写/改文件 | 稳定 | Pydantic 校验 + 工作区边界硬约束 |
| glob/grep 定位 | 较稳定 | rg 输出截断后仍够用 |
| 问候 / 简单问答 | 稳定 | 提示词禁止滥用工具 |

## 容易翻车的任务

| 类型 | 表现 | 主因（对应下周主题） |
|------|------|----------------------|
| 多文件重构、跨模块推理 | 易漏改 | **上下文变长后注意力稀释**（Day 8–9 预算与压缩） |
| 长会话连续多轮 | 后期变笨 | 默认窗口 + 历史膨胀（Day 8–9） |
| rm / git push 等破坏性 bash | 有时犹豫或误执行 | **缺权限管道**（Day 11）；提示词只是软约束 |
| 超大工具输出 | 刷屏、挤占上下文 | Day 9 工具输出裁剪 |
| 复杂 UI / 前端 | 未覆盖 | 工具集尚无浏览器能力 |

## 架构收获

- **事件流解耦**：引擎 yield 事件，TUI / REPL / 未来 SSE 都是消费者（Day 25 伏笔）。
- **软约束 vs 硬约束**：风格靠提示词 + AGENTS.md；安全靠代码校验与后续权限层。
- **少即是多**：系统提示词 ~500 token 即可驱动「改完必测」等行为。
